**Status: Beta** – tested in a demo environment, not yet in customer
production.

Engineering change orders on top of OmniaGit odooplm
*activity_validation* (not modified):

- **ECR → ECO**: when an odooplm change request moves to "ECO", an ECO
  document is created with the request's item as the first affected item
  (button *Open ECO* on the request).
- **Affected items**: PLM items (templates, variant families included)
  that get a new revision; **BoM versions** (OCA *mrp_bom_version*):
  sellable/configurable products whose BoM gets a new draft version.
- **Effectivity policy** on the ECO, applied when each revision is
  released: *use up old stock first*, *immediately* or *from a date*.
- **Impact analysis** from the ECO: where used (fixed lines;
  attribute-match lines and component families when the configurator
  modules are installed), stock per revision, open MOs (components and
  produced), RFQs, confirmed POs and open sales of BoM-versioned
  products.
- **Closing**: when all revisions are released the ECO closes, BoM
  versions are activated (on the date for date effectivity, by a
  scheduled action), the old versions become historical and the ECR is
  marked done.

Configuration
=============

- Users: *OdooPLM - Integration User* (create and edit ECOs;
  Manufacturing users can read them), *Activity User* (odooplm
  activity_validation) for the change request (ECR) steps, *OdooPLM -
  PLM / Release Users* to release revisions, *Products: Create* to
  create revisions.
- ECO numbers come from the sequence *Engineering change order*
  (``ECO-0001``).
- The scheduled action *PLM: activate BoM versions of ECOs effective
  today* (hourly) activates BoM versions of ECOs with date effectivity.

Usage
=====

1. Approve the change request (odooplm activity, *ECO* button) → ECO is
   created.
2. On the ECO add affected items and BoM versions, choose the
   effectivity, *Analyse impact*.
3. *Create revisions*: new revisions (with variants, codes, vendors,
   documents, BoMs) and draft BoM versions. Edit them.
4. Confirm and release each revision in PLM. The last release closes the
   ECO.
5. *Open orders* proposes moving unstarted MOs and RFQs to the new
   revision.
